# Overlap review

Access date: 2026-11-23.

TrialStress asks whether a biostatistician can audit a hypothetical fixed 1:1 trial with a continuous endpoint when accrual, independent dropout, or the assumed mean difference changes. The acceptance case held constant in this review is the full-data baseline: 100 participants, equal allocation, mean difference 0.6, common standard deviation 1, two-sided alpha 0.05, no dropout, and every participant analyzed. The expected artifact is the power of the equal-variance two-sample t-test. The acceptance metric is agreement with the noncentral-t power, which is 0.8438754224639083 for that fixture.

No external dataset is used. Contenders below simulate their own data or evaluate a formula. TrialStress will author its fixtures in this repository.

## Probes

### Shared full-data fixture (observed)

Command, run on this machine with NumPy 2.2.6, SciPy 1.15.3, and statsmodels 0.14.5:

```python
import math
from scipy import stats
from statsmodels.stats.power import TTestIndPower

n1 = n2 = 50
delta = 0.6
sigma = 1.0
alpha = 0.05
df = n1 + n2 - 2
ncp = delta / (sigma * math.sqrt(1 / n1 + 1 / n2))
t_crit = stats.t.ppf(1 - alpha / 2, df)
scipy_power = stats.nct.sf(t_crit, df, ncp) + stats.nct.cdf(-t_crit, df, ncp)
sm_power = TTestIndPower().power(
    effect_size=delta / sigma,
    nobs1=n1,
    alpha=alpha,
    ratio=n2 / n1,
    alternative="two-sided",
)
```

Observed values:

- SciPy noncentral-t power: 0.8438754224639083
- statsmodels 0.14.5 power: 0.8438754224639081
- absolute difference: 2.22e-16

The null formula returns 0.05. statsmodels is a comparator only. It is not a TrialStress dependency. Primary pages: [SciPy](https://scipy.org/) and [statsmodels TTestIndPower](https://www.statsmodels.org/stable/generated/statsmodels.stats.power.TTestIndPower.html).

### rpact (documentation)

- Primary URL: https://github.com/rpact-com/rpact
- Docs: https://docs.rpact.org/reference/getPowerMeans.html and https://docs.rpact.org/reference/getSimulationMeans.html
- Commit inspected: `68538fbdd01d25c0516b488d82a5fc09b63362a9` (2026-11-17)
- Version: 5.0.0, dated 2026-11-16 in `DESCRIPTION`
- License: LGPL-3 (`LICENSE.md` and `DESCRIPTION`)
- Dataset terms: not applicable; calculations and simulations are generated by the package

`getPowerMeans` returns power for one-sample or two-sample means. With `normalApproximation = FALSE` the documented calculation uses the t distribution. That is the right cross-check for the full-data baseline, using `maxNumberOfSubjects = 100`, `alternative = 0.6`, `stDev = 1`, `allocationRatioPlanned = 1`, and a two-sided test.

`getSimulationMeans` simulates means at a planned subject count. Its arguments do not include accrual, a calendar readout, or dropout. Dropout handling in the same package is part of the survival design and simulation functions. rpact therefore does not, by itself, explain how many continuous outcomes are still analyzable when accrual slows or when dropout removes scores. A numeric rpact run was not executed here: R is not installed on this image, and the full-data formula was already checked with statsmodels. That numeric rpact call remains an optional unresolved check, not a missing fixture.

### Merck simtrial (documentation)

- Primary URL: https://github.com/Merck/simtrial
- Docs: https://merck.github.io/simtrial/ and the fixed-design vignette `vignettes/sim_fixed_design_simple.Rmd`
- Commit inspected: `edf78a969d85b79a8727e125027f4dbdbb249405` (2026-10-01)
- Version: 1.1.0 in `DESCRIPTION` on that commit
- License: GPL-3 in `DESCRIPTION`. The license header also offers any later version.
- Dataset terms: not applicable; enrollment, survival, and dropout times are simulated

The package description limits the primary intent to time-to-event outcomes, with piecewise constant enrollment and piecewise exponential failure and dropout. `sim_fixed_n` simulates a two-arm time-to-event design. The shared fixture's continuous mobility score is a different endpoint, so the acceptance metric cannot be held constant inside simtrial without changing the scientific question. GPL-3 code will not be copied into this MIT repository. No simtrial run was executed because R is not installed and the endpoint does not match.

### TrialSimulator (documentation)

- Primary URL: https://github.com/zhangh12/TrialSimulator
- Docs: https://zhangh12.github.io/TrialSimulator/ and the non-time-to-event endpoint vignette
- Commit inspected: `89278155433cff9b7ea960ad2b7c9e48c83e1653` (2026-10-16)
- Version: 1.39.0 in `DESCRIPTION`
- License: MIT + file LICENSE
- Dataset terms: not applicable; endpoints are generated by user-supplied random generators

This is the closest general simulator. A normal endpoint can be declared with `type = "non-tte"` and a `readout` lag. `StaggeredRecruiter` uses a piecewise constant rate, places the first patient at `1/rate`, and spaces later patients by `1/rate`. Dropout is a time-to-dropout draw. Analysis, including what happens when an arm has too few complete cases, is user code. The weekly batch calendar in the TrialStress proof case (week 0 through week 20, four arrivals per week, 84 enrolled and 68 analyzable) is a different accrual clock. TrialSimulator can be a host for that study, but it does not already ship the labeled invalid-analysis report or the preregistered tolerance check. No TrialSimulator run was executed because R is not installed.

## What already matches

The full-data power number is not a reason to start a new statistical method. SciPy, statsmodels, and rpact's means power function already implement it. simtrial and TrialSimulator already simulate staggered entry and dropout for their own endpoint definitions.

What does not already match is one auditable command that:

- fixes a weekly calendar indexed from week 0
- keeps a balanced 1:1 assignment of the full plan
- drops continuous scores independently by arm
- includes an outcome due on the readout week and excludes one due the next week
- counts an invalid complete-case t-test in the unconditional denominator
- withholds the conditional rejection frequency when no analysis is valid
- shows Monte Carlo uncertainty separately from uncertainty about a real effect
- compares those counts and frequencies with an identified baseline

## Decision

**Proceed.** Keep the MVP narrow: synthetic hypothetical mobility scores, a fixed two-arm design, and a local Python command-line report. Do not add rpact, simtrial, TrialSimulator, or statsmodels as runtime dependencies. Do not copy GPL-3 simtrial code. An optional later cross-check is `rpact::getPowerMeans` on the full-data fixture only.

Contribution or integration is not recommended as the implementation path. simtrial would have to change endpoints. TrialSimulator would still need the calendar convention, the invalid-analysis rules, and the tolerance gate written by the user. rpact already answers the full-data formula and does not track lost continuous outcomes.

## Remaining uncertainties

- rpact 5.0.0 was not executed in R, so its full-data power number was not observed directly. The formula it documents was observed through SciPy and statsmodels.
- TrialSimulator's MIT license file beyond the `DESCRIPTION` line was not re-read in full.
- Package versions move. The commits and versions above are the ones inspected on 2026-11-23.
